# Fetch into DuckDB and SQL over the Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two ways to use SQL, both on DuckDB: `fetch(..., to="x.duckdb")` (`--out x.duckdb`) builds a local database, one table per source, a fetch at a time; and `store.sql("SELECT ...")` with `data-pipeline sql` answer one SELECT over the store's Parquet files in place, each source read as its latest rows, as of a day, or with every stored version.

**Architecture:** A new module `store/sql.py` opens a DuckDB database in memory for each call and defines views over the store's own files: per source `<source>_versions` (every stored row) and `<source>` (per key the row `storage.latest` or `storage.as_of` would choose, by window functions in SQL, sorted as those functions sort), and `store_index`. DuckDB's parser checks the query before anything runs; only one SELECT passes. `fetching.py`'s registry of destinations by extension becomes a registry of writers, and `.duckdb` joins it: a writer that, in one transaction, creates the source's table, adds the columns it lacks, deletes the rows of the ids that arrived and inserts the new ones by name. The `sql` command reuses that registry for `--out`.

**Tech Stack:** Python 3.12+, pandas, pyarrow, DuckDB (new: `duckdb>=1.1,<3`), click, pytest, ruff, mypy strict.

**Spec:** `docs/superpowers/specs/2026-10-23-sql-design.md`

**Decided here, beyond the spec:**
- Order: SQL over the store comes first, so the quoting of a DuckDB name (`quote`) lives in `store/sql.py` and `fetching.py` imports it; the store never imports `fetching`.
- A table source's views carry `id` first, the catalog id the row's file is named after (`AAPL`), then the columns of `Store.table`. The spec says "columns as `Store.table` returns them", but `sec_xbrl`'s key has no company: without `id`, the facts of two companies could not be told apart. A series source's view is `key, date, period, value`, as the spec says.
- `<source>_versions` of a series holds the stored columns (`key, period, date, value, projection, fetched_at, published_at`), sorted per key as `Store.revisions` sorts. Of a table: `id`, the columns of `Store.table`, `fetched_at`, `published_at`, in the order stored. A column a file still has but the schema no longer lists (Comtrade's old `level`) is left out, as `Store.table` leaves it out.
- Every view is ordered as `Store.series` and `Store.table` order their rows, so `SELECT * FROM <source>` reads in the store's order. Rows that tie on every stamp: the later one in its file wins, as pandas keeps it.
- Every view is built in SQL. None needed the store's functions (see "Verified").
- The stamps are cast to `TIMESTAMPTZ` (microseconds) as they are read. DuckDB 2.0 reads them as `TIMESTAMPTZ_NS`, which will not compare with a `TIMESTAMPTZ` and reaches pandas without its zone. The store's stamps come from Python datetimes, whole microseconds, so nothing is lost; `as_of` is floored to the microsecond, which keeps `<=` exact.
- The connection runs in UTC (`TimeZone`) and may not install extensions (`autoinstall_known_extensions` off). Without the second, a SELECT that reads an `https://` address would download DuckDB's `httpfs` into the user's home folder, and the spec says `sql` never writes a file.
- Messages: `only one SELECT is accepted, not CREATE` (the type DuckDB's parser gives: `INSTALL` reads as `LOAD`), `..., not 2 statements`, `..., and the query is empty`. A query DuckDB refuses, a syntax error included: `the query failed: <DuckDB's message>` and a last line `the names a query can read: ...`.
- A source of documents (`sec_filings`) has no name; the README says to read it with `store.documents`.
- `fetch` into `.duckdb`: the rows replaced are those of the ids that arrived. An id that failed, or that worked and brought no rows, keeps its rows (the spec's "ids of this fetch" read the safe way). The schema changes (CREATE, ALTER) are part of the one transaction and roll back with it. Column types are DuckDB's reading of the frame, except that a text column without any value is created as text: DuckDB types it `"NULL"` (2.0) or `INTEGER` (1.1), and either refuses the text of a later fetch.
- The registry: `ENCODERS` and `_File` become `WRITERS` (a `Writer` protocol that takes `table` and `by_id`) and `Destination`; `_destination` becomes `destination(to, where)` so the `sql` command checks `--out` by the same rules; `WRITE_ERRORS = (OSError, duckdb.Error)`. The reason of a write error is put on one line: DuckDB's lock message spans several.
- A table of the same name in another case (`FAKE`) is the same table to DuckDB, so the writer looks for the table and its columns without regard to case, and creates a table with `CREATE TABLE`, never `CREATE OR REPLACE`, when `by_id`: a table of the user's is never replaced by a fetch.
- An extension it does not know: "the file must end in .parquet, .csv or .duckdb".
- `sql --out x.duckdb` writes the table `result`, replaced whole, and leaves the file's other tables alone. The spec gives `sql` the destinations of `fetch` but a query's rows have neither a source to name the table nor ids to replace.
- `sql` exits with 1 when `--out` cannot be written, as `fetch` does. The spec lists only 0 and 2.
- `sql` prints `N rows, M columns`, the header and the first ten rows; a time prints as a day when it is a midnight without a zone, otherwise in ISO form with its zone.
- The test of a locked file holds the file open in a second Python process, as another program would; it does not mock DuckDB.

```python
def observation(key, period, day, value, fetched, published=None, projection=False):
    return {
        "key": key,
        "period": period,
        "date": day,
        "value": value,
        "projection": projection,
        "fetched_at": fetched,

    }


SERIES = [

    observation("fake:AAA", "2026-01", "2026-01-31", 1.5, T2),  # revised
    observation("fake:AAA", "2026-02", "2026-02-28", 2.0, T1),
    observation("fake:AAA", "2026-02", "2026-02-28", math.nan, T2),  # revised to missing
    observation("fake:AAA", "2026-03", "2026-03-31", 3.0, T1, projection=True),
    observation("fake:AAA", "2026-03", "2026-03-31", 3.1, T2),
    observation("fake:AAA", "2026-Q1", "2026-03-31", 9.0, T1),  # the date of 2026-03: fetched first, read first
    observation("fake:AAA", "2026-04", "2026-04-30", 4.0, T2, P2),
    observation("fake:AAA", "2026-04", "2026-04-30", 4.4, T2),  # no publication: the earlier of one fetch
    observation("fake:BBB", "2026-01", "2026-01-31", 10.0, T1, P0),

def price(ticker, day, close, fetched, note=None):
    return st.table_frame(
        [{"ticker": ticker, "period": day, "date": day, "close": close, "note": note}], PLAIN, fetched

def fact(concept, value, published, fetched, form="10-K"):
    row = {"concept": concept, "end": "2025-12-31", "date": "2025-12-31", "value": value, "form": form}
    return st.table_frame([{**row, "published_at": published}], VERSIONED, fetched)


def index_row(key, kind):
    source, source_id = key.split(":")
    return {"key": key, "source": source, "source_id": source_id, "name": f"Name of {source_id}", "kind": kind}


@pytest.fixture
def store(tmp_path):

    storage = st.Storage(tmp_path)

    storage.write_index(st.typed(keys, st.INDEX_DTYPES))

def plain_values(frame):
    """The frame's values as Python objects, a missing one as None: DuckDB gives None for missing
    text where pandas has NaN, and microseconds where the store has nanoseconds."""
    values = frame.reset_index(drop=True).astype(object)
    return values.where(values.notna(), None)


def same(found, expected):
    pd.testing.assert_frame_equal(plain_values(found), plain_values(expected))


def joined(parts):
    """The frames one after another; pandas warns when it joins empty ones."""
    filled = [part for part in parts if not part.empty]
    return pd.concat(filled, ignore_index=True) if filled else parts[0]

@pytest.mark.parametrize("moment", MOMENTS)
@pytest.mark.parametrize(
    ("key", "query"),
    [
        ("fake:AAA", "SELECT date, period, value FROM fake WHERE key = 'fake:AAA'"),
        ("fake:BBB", "SELECT date, period, value FROM fake WHERE key = 'fake:BBB'"),

)
def test_a_series_reads_as_store_series_reads_it(store, moment, key, query):
    same(store.sql(query, as_of=moment), store.series(key, as_of=moment))


@pytest.mark.parametrize("moment", MOMENTS)
def test_a_series_source_holds_every_key_in_the_order_of_store_series(store, moment):
    expected = joined([store.series(key, as_of=moment).assign(key=key) for key in ("fake:AAA", "fake:BBB")])
    same(store.sql("SELECT * FROM fake", as_of=moment), expected[["key", "date", "period", "value"]])


@pytest.mark.parametrize("moment", MOMENTS)
@pytest.mark.parametrize(("source", "names"), [("plain", ["XAAA", "XBBB", "XC.C"]), ("versioned", ["ACME", "BETA"])])
def test_a_table_source_reads_as_store_table_reads_it(store, moment, source, names):
    found = store.sql(f"SELECT * FROM {source}", as_of=moment)  # noqa: S608 - a name of the test
    parts = [store.table(source, name, as_of=moment) for name in names]
    expected = joined([part.assign(id=name) for name, part in zip(names, parts, strict=True)])
    same(found, expected[["id", *expected.columns[:-1]]])
    same(found.drop(columns="id"), store.table(source, as_of=moment))

# -- what sql refuses, and how it fails ---------------------------------------------------------


@pytest.mark.parametrize(
    ("query", "found"),
    [
        ("CREATE TABLE copy AS SELECT * FROM fake", "not CREATE"),
        ("INSERT INTO fake_versions SELECT * FROM fake_versions", "not INSERT"),
        ("COPY (SELECT * FROM fake) TO 'out.csv'", "not COPY"),
        ("ATTACH 'other.duckdb'", "not ATTACH"),
        ("INSTALL httpfs", "not LOAD"),
        ("SET threads = 1", "not SET"),
        ("SELECT 1; SELECT 2", "not 2 statements"),
        ("  ", "and the query is empty"),
    ],
)
def test_anything_but_one_select_is_refused_before_it_runs(store, tmp_path, monkeypatch, query, found):
    monkeypatch.chdir(tmp_path)
    with pytest.raises(StoreError, match=f"^only one SELECT is accepted, {found}$"):
        store.sql(query)
    assert not (tmp_path / "out.csv").exists()
    assert not (tmp_path / "other.duckdb").exists()


def test_a_select_that_starts_with_with_is_accepted(store):
    query = "WITH latest AS (SELECT * FROM fake) SELECT count(*) AS rows FROM latest; "
    assert store.sql(query)["rows"].tolist() == [7]


def test_a_name_that_does_not_exist_fails_with_duckdbs_message_and_the_names_defined(store):
    with pytest.raises(StoreError) as caught:
        store.sql("SELECT * FROM prices")
    message = str(caught.value)
    assert "Table with name prices does not exist" in message
    assert message.splitlines()[-1] == (
        "the names a query can read: fake, fake_versions, plain, plain_versions, store_index, "
        "versioned, versioned_versions"
    )


def test_a_query_duckdb_cannot_parse_fails_with_its_message(store):
```

```python
"""SQL over the store: one SELECT, answered by DuckDB from the store's own Parquet files.

    store.sql("SELECT ticker, period, close FROM sharadar_prices WHERE period = '2026-10-22'")
    store.sql("SELECT * FROM sec_xbrl WHERE concept = 'Revenues'", as_of="2024-03-01")

Each call opens a new DuckDB database in memory and, before the query runs, defines for every
source with stored data:

  <source>_versions  every stored row, read from the source's files, with `fetched_at` and
                     `published_at`
  <source>           the rows Store.series or Store.table returns: per key its latest version, or
                     the one in force at `as_of`
  store_index        the index, as Store.index() returns it

A series source gives `key` and then the columns of Store.series (`date`, `period`, `value`); a
table source gives `id`, the catalog id whose table holds the row, and then the columns of
Store.table. Its files are read together by column name, so a column a file was written without
reads as missing.

The views choose versions with window functions, by the rules of `storage.latest` and
`storage.as_of`, and sort their rows as those functions do (tests compare them row for row): per
key (a series: key and period; a table: its id and key columns) the row fetched last, and among
the rows of one fetch the one published last; for a versioned table, and as of a moment, the row
known last, known from its publication or else its fetch, and among those the one fetched last.
Rows that tie on all of it: the later one in its file. A series leaves out missing values and
projections, as Store.series does.

Only one statement runs, and only a SELECT (`WITH ... SELECT` too): DuckDB's parser reads the
query first, and anything else is refused before it runs. The database lives in memory and may
not install extensions, and the store's files are only read, so a query changes no file. It can
still read other files on the machine (`read_csv('...')`), with the rights of whoever runs it.
"""

import pathlib
from collections.abc import Sequence

import duckdb
import pandas as pd

from data_pipeline.store import storage as st
from data_pipeline.store.errors import StoreError

INDEX = "store_index"
VERSIONS = "_versions"
ONLY_SELECT = "only one SELECT is accepted"
# Times in UTC, as the store writes them; no extension downloaded or written to disk by a query
SETTINGS: dict[str, str | bool | int | float | list[str]] = {
    "TimeZone": "UTC",
    "autoinstall_known_extensions": False,
}
SERIES_COLUMNS = ["key", "period", "date", "value", "projection"]


def quote(name: str) -> str:
    """A name as a DuckDB identifier, quoted whatever it holds."""
    return '"' + name.replace('"', '""') + '"'


def _text(value: str) -> str:
    """Text as a DuckDB literal."""
    return "'" + value.replace("'", "''") + "'"


def answer(storage: st.Storage, query: str, moment: pd.Timestamp | None) -> pd.DataFrame:
    """The rows of `query`, a single SELECT, over the views of `storage` (see the module),
    each source read as of `moment` when one is given. StoreError for anything but one SELECT,
    before it runs, and for a query DuckDB refuses, with its message and the names defined."""
    series = storage.series_sources()
    tables = storage.table_sources()
    names = sorted([*series, *tables, *(source + VERSIONS for source in [*series, *tables]), INDEX])
    _check(query, names)
    with duckdb.connect(":memory:", config=SETTINGS) as connection:
        try:
            for source in series:
                _series_views(connection, storage, source, moment)
            for source in tables:
                _table_views(connection, storage, source, moment)
            connection.register(INDEX, storage.read_index())
            return connection.execute(query).df()
        except duckdb.Error as exc:
            raise _failed(exc, names) from exc


def _failed(error: duckdb.Error, names: Sequence[str]) -> StoreError:
    return StoreError(f"the query failed: {error}\nthe names a query can read: {', '.join(names)}")


def _check(query: str, names: Sequence[str]) -> None:
    """Refuse, before anything runs, a query that is not exactly one SELECT."""
    try:
        statements = duckdb.extract_statements(query)
    except duckdb.Error as exc:
        raise _failed(exc, names) from exc
    if not statements:
        msg = f"{ONLY_SELECT}, and the query is empty"
        raise StoreError(msg)
    if len(statements) > 1:
        msg = f"{ONLY_SELECT}, not {len(statements)} statements"
        raise StoreError(msg)
    kind = statements[0].type
    if kind != duckdb.StatementType.SELECT:
        msg = f"{ONLY_SELECT}, not {kind.name}"
        raise StoreError(msg)


def _rows(paths: Sequence[pathlib.Path]) -> str:
    """Every row of the Parquet files, read together by column name, with `id`, the name of its
    file, and `position`, where it sits in that file. The stamps are cast to TIMESTAMPTZ: DuckDB
    reads them as TIMESTAMPTZ_NS, which compares with no other time and reaches pandas without its
    zone (the store's stamps are whole microseconds, so nothing is lost)."""
    listed = ", ".join(_text(path.as_posix()) for path in paths)
    return (
        "(SELECT parse_filename(filename, true) AS id, "  # noqa: S608 - quoted names
        "* EXCLUDE (filename, file_row_number) "
        "REPLACE (fetched_at::TIMESTAMPTZ AS fetched_at, published_at::TIMESTAMPTZ AS published_at), "
        "file_row_number AS position "
        f"FROM read_parquet([{listed}], union_by_name = true, filename = true, file_row_number = true))"
    )


def _chosen(
    rows: str,
    columns: Sequence[str],
    key: Sequence[str],
    order: Sequence[str],
    moment: pd.Timestamp | None,
    *,
    by_publication: bool,
    keep: str = "true",
) -> str:
    """A SELECT of `columns` from `rows`: per `key` the row storage.latest chooses (or, given a
    moment, storage.as_of), among those that `keep`, sorted by `order` as those functions sort.

    `rows` holds `position`: of rows that tie on every stamp, pandas keeps the later one.
    """
    if moment is None and not by_publication:
        # the row fetched last, then published last; a missing stamp is the earliest
        rank = "fetched_at DESC NULLS LAST, published_at DESC NULLS LAST"
        stamps = "fetched_at NULLS FIRST, published_at NULLS FIRST"
        visible = "true"
    else:
        # the row known last, then fetched last; a missing stamp is the latest
        rank = "known_at DESC NULLS FIRST, fetched_at DESC NULLS FIRST"
        stamps = "known_at NULLS LAST, fetched_at NULLS LAST"
        visible = "true" if moment is None else f"known_at <= TIMESTAMPTZ {_text(moment.floor('us').isoformat())}"
    partition = ", ".join(quote(column) for column in key)
    sort = ", ".join(f"{quote(column)} NULLS LAST" for column in order)
    selected = ", ".join(quote(column) for column in columns)
    return (
        f"SELECT {selected} FROM ("  # noqa: S608 - quoted names
        f"SELECT *, row_number() OVER (PARTITION BY {partition} ORDER BY {rank}, position DESC) AS chosen "
        f"FROM (SELECT *, coalesce(published_at, fetched_at) AS known_at FROM {rows}) WHERE {visible}"
        f") WHERE chosen = 1 AND {keep} ORDER BY {sort}, {stamps}, position"
    )


def _series_views(
    connection: duckdb.DuckDBPyConnection, storage: st.Storage, source: str, moment: pd.Timestamp | None
) -> None:
    rows = _rows([storage.series_path(source)])
    every = ", ".join(quote(column) for column in [*SERIES_COLUMNS, *st.STAMP_COLUMNS])
    connection.execute(
        f"CREATE VIEW {quote(source + VERSIONS)} AS SELECT {every} FROM {rows} "  # noqa: S608 - quoted names
        'ORDER BY "key", "date", fetched_at NULLS FIRST, published_at NULLS FIRST, position'
    )
    current = _chosen(
        rows,
        ["key", "date", "period", "value"],
        st.KEY,
        st.SERIES_ORDER,
        moment,
        by_publication=False,
        keep="value IS NOT NULL AND NOT isnan(value) AND NOT projection",
    )
    connection.execute(f"CREATE VIEW {quote(source)} AS {current}")


def _table_views(
    connection: duckdb.DuckDBPyConnection, storage: st.Storage, source: str, moment: pd.Timestamp | None
) -> None:
    schema = storage.table_schema(source)
    rows = _rows([storage.table_path(source, name) for name in storage.table_names(source)])
    every = ", ".join(quote(column) for column in ["id", *schema.columns, *st.STAMP_COLUMNS])
    connection.execute(
        f"CREATE VIEW {quote(source + VERSIONS)} AS SELECT {every} "  # noqa: S608 - quoted names
        f"FROM {rows} ORDER BY id, position"
    )
    current = _chosen(
        rows,
        ["id", *schema.columns],
        ["id", *schema.key_columns],
        ["id", *schema.row_order],
        moment,
        by_publication=schema.versioned,
    )
    connection.execute(f"CREATE VIEW {quote(source)} AS {current}")
```

```python
"""The `sql` command: one SELECT over the store, answered by DuckDB. Output is ASCII only.

Exit codes: 0 done, 1 the rows could not be written to --out, 2 a query refused or failed, or a
bad option.
"""

import pathlib

import click
import pandas as pd

from data_pipeline.fetching import WRITE_ERRORS, destination
from data_pipeline.store.api import Store
from data_pipeline.store.cli import PATH, SHOWN_ROWS, echo, fail, root_option
from data_pipeline.store.errors import StoreError
from data_pipeline.store.sync import EXIT_FAILURES, EXIT_OK

WHERE = "sql"
RESULT = "result"  # the table of a .duckdb file the rows go to


def cell(value: object) -> str:
    """A value as the console shows it: a day without its midnight, a moment in ISO form."""
    if isinstance(value, pd.Timestamp):
        if value.tzinfo is None and value == value.normalize():
            return value.date().isoformat()
        return value.isoformat()
    return str(value)


@click.group()
def cli() -> None:
    """SQL over the store."""


@cli.command("sql")
@root_option
@click.argument("query")
@click.option("--as-of", "as_of", default=None, help="Read each source as it was known on this date (YYYY-MM-DD).")
@click.option(
    "--out",
    type=PATH,
    default=None,
    help="Write every row to this .parquet or .csv file, replacing it, or to the table `result` of a .duckdb file.",
)
def sql_command(*, root: pathlib.Path, query: str, as_of: str | None, out: pathlib.Path | None) -> None:
    """Answer QUERY, one SELECT over the store: the first rows, or every row to --out.

    Each source with data is two names: SOURCE, its latest rows (as of --as-of when given), and
    SOURCE_versions, every row stored; store_index is the index. Nothing in the store changes.
    """
    try:
        target = destination(out, where=WHERE)
        data = Store(root).sql(query, as_of=as_of)
    except StoreError as exc:
        raise fail(exc) from exc
    echo(f"{len(data)} rows, {len(data.columns)} columns")
    if target is None:
        echo("  ".join(str(column) for column in data.columns))
        for values in data.head(SHOWN_ROWS).itertuples(index=False):
            echo("  ".join(cell(value) for value in values))
        if len(data) > SHOWN_ROWS:
            echo(f"[i]   the first {SHOWN_ROWS} of {len(data)} rows; use --out FILE for all of them")
        raise SystemExit(EXIT_OK)
    try:
        target.write(data, table=RESULT, by_id=False)
    except WRITE_ERRORS as exc:
        echo(f"[x]   could not write {out}: {type(exc).__name__}: {' '.join(str(exc).split())}")
        raise SystemExit(EXIT_FAILURES) from exc
    echo(f"[ok]  written to {out}")
    raise SystemExit(EXIT_OK)
```

````markdown
## SQL

The store answers SQL. [DuckDB](https://duckdb.org) reads its Parquet files in place, with no copy
and no index to keep:

```python
store.sql("SELECT ticker, period, close FROM sharadar_prices WHERE period = '2026-10-22'")
store.sql("SELECT * FROM sharadar_fundamentals WHERE dimension = 'ARQ'", as_of="2024-03-01")
store.sql("SELECT * FROM sharadar_prices_versions WHERE ticker = 'AAPL'")  # every stored row
```

```bash
data-pipeline sql --root D:/data "SELECT * FROM fred WHERE key = 'fred:UNRATE'"
data-pipeline sql --root D:/data "SELECT * FROM sec_xbrl" --as-of 2024-03-01 --out facts.parquet
```

`store.sql` returns a pandas DataFrame. Each source with data in the store gives a query two
names, and the index a third:

| Name | Rows |
|---|---|
| `<source>` (`fred`, `sharadar_prices`, ...) | what `store.series` or `store.table` gives: the latest version of each key, or the one in force at `as_of` |
| `<source>_versions` | every row stored, with `fetched_at` and `published_at` |
| `store_index` | the index, as `store.index()` gives it |

A series source has the columns `key` (`fred:UNRATE`), `date`, `period` and `value`, without
missing values and projections, as `store.series` reads it. A table source has `id`, the id of
its catalog entry (`AAPL`), and then the columns `store.table` gives. `as_of` (`--as-of`) takes
what `store.table` takes, with the same meaning. Documents (`sec_filings`) have no name: read them
with `store.documents`.

`sql` runs one `SELECT` (or `WITH ... SELECT`) per call. Anything else (`CREATE`, `INSERT`,
`COPY ... TO`, `ATTACH`, `INSTALL`, `SET`, or two statements) is refused before it runs, so a
query never writes a file or changes the store. A query DuckDB refuses, such as a name that does
not exist, raises `StoreError` with DuckDB's message and the names a query can read; the command
prints them and exits with 2. A `SELECT` can still read other files on your computer (`SELECT *
FROM read_csv('C:/notes.csv')`): it runs with your rights, like any program you run.

Without `--out`, the command prints the first rows. `--out` takes the files `fetch` writes: a
`.parquet` or `.csv` file is replaced, and in a `.duckdb` file the rows replace the table
`result`, while the file's other tables stay. The command exits with 1 when the file cannot be
written.
````
